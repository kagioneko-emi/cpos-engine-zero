# AI White-Hatter System Spec

## 目的

この仕様は、**バグバウンティや許可済みの検証環境**で使うための、
`Codex` を司令塔にした **AI ホワイトハッカー運用**を定義する。

狙いは「攻撃の自動化」ではなく、次の作業を速く・漏れなく・安全に回すこと。

- 既存リポジトリの確認
- 仕様差分の整理
- 再現手順の最小化
- 証跡の収集
- 報告書の整形

## 前提

- 対象は **スコープ内のみ**
- 許可されたリポジトリ・許可されたデータのみを使う
- 秘密情報、個人情報、本番データの保存はしない
- 破壊的操作、過負荷、権限逸脱はしない
- 再現は最小限に留める
- 最終判断は必ず人間が行う

## 既存リポジトリの役割分担

既にある資産は、以下のように役割分担する。

### 1. `cpos_defensive_agent`
基幹ランタイム。

- タスク管理
- Human Escalation
- メタデータ中心の記録
- 安全ガード
- レポート・ダッシュボード

### 2. `ai-red-teaming-engine`
検査・解析エンジン。

- 静的解析
- LLM 支援レビュー
- カスタムルール
- 差分比較
- 監査結果の構造化

### 3. `ai-instruction-tape`
短い指令形式。

- タスクの圧縮表現
- 人間/AI 間のルーティング
- ログとハンドオフの軽量化

### 4. `ai-review-matrix`
レビュー観点の整理。

- セキュリティ
- 法務/倫理
- 読みやすさ
- リスク区分

### 5. `ai-role-assignment-matrix`
AI の役割配分。

- Codex: 技術検証、手順、ログ、コード
- Claude: 深い読解、リスク整理、差分把握
- Gemini: 広い調査、候補洗い出し、要約

### 6. `claude-code-security-kit`
実行前の安全確認。

- 危険コマンドの抑止
- 秘密情報の誤コミット防止
- 構成ファイルの安全確認

## 役割定義

### Codex

司令塔として動く。

- タスク分解
- ローカルファイル確認
- ログ確認
- テスト実行
- 証跡整理
- レポート草案生成
- 次アクション決定の補助

### Gemini

広く拾う役。

- 関連技術の整理
- 類似事例の候補出し
- 仕様の読みやすい要約
- 横断的な観点の洗い出し

### Claude Code

深く読む役。

- コードの流れの追跡
- 変更差分の意味づけ
- 再現の筋道整理
- 実装の整合性確認

## 「使えるリポ」をどう扱うか

使えるリポは積極的に使うが、以下の分類で管理する。

### `allowed`
自由に参照してよい

### `reference_only`
比較・読解専用

### `test_only`
検証用に限定

### `blocked`
触らない

### `scope_unknown`
まずスコープ確認が必要

## リポ統合の優先順位

1. **既存の防御・監査基盤を再利用**
2. **共通化できる比較ロジックを抽出**
3. **再現・証跡・報告のテンプレを統一**
4. **最後に必要な機能だけ追加実装**

新規作成より、まず比較と流用を優先する。

## 作業フロー

### Phase 1: 既存資産確認

- 既存リポの README / 仕様 / テストを確認
- 似た機能を持つモジュールを抽出
- 再利用できるテンプレ・ルール・スクリプトを洗い出す

### Phase 2: 仕様化

- 役割分担
- 入力形式
- 出力形式
- 記録形式
- 禁止事項
- 認可フロー

### Phase 3: 実行

- ローカル確認
- 最小再現
- 比較
- 証跡保存

### Phase 4: 報告

- タイトル
- 影響
- 再現手順
- 期待結果 / 実結果
- 必要最低限のログ
- 修正の方向性

## 推奨アーティファクト

### 1. タスクメモ

- 何を確認するか
- どのリポを使うか
- どの AI を使うか
- 何を保存するか

### 2. 比較表

- 対象
- 参照元
- 差分
- 影響
- 再現性

### 3. 証跡テンプレ

```md
# Finding
- Title:
- Scope:
- Repo(s):
- AI roles:
- Severity:
- Hypothesis:
- Reproduction:
- Expected:
- Actual:
- Evidence:
- Notes:
```

### 4. 短縮指令

`ai-instruction-tape` を使う場合は、短いタスク指令でルーティングする。

例:

```text
security / ctx4 / audit / priority9
```

## 安全ガード

- スコープ外アクセス禁止
- 本番データ保存禁止
- 秘密情報のログ出力禁止
- 破壊的操作は事前確認
- 変更は最小限
- 連続リクエストの出しすぎ禁止
- 人間の承認が必要なものは必ず止める

## 実務上の使い分け

- **Codex**: 司令塔
- **Gemini**: 広く拾う
- **Claude**: 深く詰める
- **既存リポ**: 素材
- **テープ/記録**: 証跡と再利用資産

## 次の実装候補

この仕様を実装に落とすなら、次の順がよい。

1. リポ分類器
2. 比較テンプレ生成
3. 証跡テンプレ生成
4. AI 役割割り当てテンプレ
5. Scope Gate
6. 報告書ジェネレータ

## まとめ

このシステムは、

> 「AIで攻める」ではなく  
> 「AIで調査・比較・再現・報告を速くする」

ための運用基盤である。

バグバウンティや許可済み検証では、既存の資産を混ぜるほど強くなる。  
ただし、最後までスコープ管理と人間の最終確認は外さない。
